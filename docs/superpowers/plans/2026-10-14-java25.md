## Library Investigation (2026-10-14)

- Official [Java API documentation](https://dev.languagetool.org/java-api.html)
  requires Java 17 since 6.6, requires one language instance, and specifies
  `Languages.getLanguageForShortCode`. Each thread needs its own `JLanguageTool`.
- Overriding only the plugin dependencies to 6.8 fails because the existing
  `new AmericanEnglish()` call conflicts with LanguageTool's internal registry.
  The stack trace and 6.8 constructor bytecode confirm duplicate instantiation.
- A standalone probe using the documented factory detected `speling` in both
  en-US and en-GB and created a second checker successfully on installed Java
  17.0.7, 21.0.7 and 25.0.4. The global XML limit property remained unset.
  Logs: `/private/tmp/spellcheck-lt68-probe/result-*.log`.
  This is library evidence, not Maven plugin integration coverage.
- The probe used the consumer plugin's resolved JARs plus Maven's SLF4J API.
  No logging provider was installed for this standalone probe; SLF4J warned and
  used its no-operation logger. Maven logging still needs integration verification.
- The 6.8 parent POM uses Jackson 2.18.0; this plugin pins 2.15.3. Dependency
  alignment remains necessary even though the narrow spelling probe passed.
- Official [development changelog](https://github.com/languagetool-org/languagetool/blob/master/languagetool-standalone/CHANGES.md)
  lists Java 17 through 21 under unreleased 6.9. The official repository's
  [Java 25 migration PR](https://github.com/languagetool-org/languagetool/pull/12161)
  is open. Neither establishes released 6.8 support for Java 25; report our
  observed compatibility separately from upstream support.

### LanguageTool Migration Results

LanguageTool migration is implemented. The broader configuration, file-selection,
and report corrections above remain open; this verification does not close them.

- LanguageTool 6.8 and Jackson BOM 2.18.0 are configured. Direct Jackson annotation
  usage is declared. Dependency analysis runs during verification and fails on
  warnings; reflective language-module and test-container dependencies are named.
- Language instances use the official registry. Checkers remain separate per
  execution. Unsupported languages, missing dictionaries, malformed text, and
  checking errors fail instead of silently passing.
- Deprecated match positions were replaced with offsets that handle LF, CRLF,
  and CR. Plugin metadata declares Java 17 and Maven 3.8.1. Plugin Tools 3.16.0
  generates the descriptor without compiler annotation processing.
- Maven 3.9.12 `clean verify` passed on installed Java 17.0.7, 21.0.7, and 25.0.4:
  34 unit tests, five consumer integration tests, and dependency analysis each.
  The consumer tests include a parallel reactor and assert report contents, so
  an unrelated build failure cannot satisfy the expected-spelling-failure test.
- Verification ran in `/private/tmp/spellcheck-lt68-final`. All 38 source/build
  files matched the working tree byte for byte. Logs are
  `/private/tmp/spellcheck-lt68-final17.log`,
  `/private/tmp/spellcheck-lt68-final21.log`, and
  `/private/tmp/spellcheck-lt68-final25.log`.
- The original working directory's `clean` still fails when deleting the empty
  `target/surefire-reports` directory, including with normal execution privileges.
  Direct removal returns `Operation not permitted`. The successful temporary-copy
  builds do not establish that cleaning the original directory is repaired.
- An empty Invoker settings file prevented use of the user's configured proxy.
  Removing the alternate settings-file configuration restored normal dependency
  resolution. No proxy address is stored in the project.
- CI now tests Java 17/21/25; hosted CI itself has not been run. Markdown lint,
  spelling checks on edited documents/code, and `git diff --check` passed.
